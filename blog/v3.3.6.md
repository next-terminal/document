# Next Terminal v3.3.6: RDP Proxy — Use Your Native RDP Client with Bastion Audit

v3.3.6 focuses on the **RDP proxy server**: access authorized RDP assets from a native remote desktop client while retaining Next Terminal unified asset management, authorization, session audit, and recording.

Browser-based RDP is convenient, but for long sessions, frequent window switching, hotkeys, file copy, or graphical tools, a native client is smoother. v3.3.6 gives you both.

## Why a Native RDP Proxy

Native clients bring closer-to-native mouse/keyboard, window scaling, clipboard/disk redirection, and less friction between browser and remote-desktop hotkeys — without leaving the bastion audit trail.

## Local Experience, Central Control

The design: **local client owns the experience, Next Terminal owns the gate.**

1. User picks an authorized RDP asset in Next Terminal
2. Server mints a short-lived ticket (`NTICKET:<id>:<secret>`, default 300s, single-use)
3. Local RDP client connects to the proxy entry
4. Proxy validates ticket and permissions, then connects to the real Windows host with stored credentials
5. Session enters the audit/recording pipeline

Users never receive the real Windows password — only a short-lived ticket bound to user and asset.

## Recording and Audit Preserved

Even via a native client, sessions are proxied, recorded, and queryable:

- Who connected, when, how long
- Replay for incidents and compliance
- Centralized permission grant/revoke

## Two Access Modes

**Direct .rdp file**: Web UI generates a ticket and downloads an `.rdp` file for the local client. Simple, but requires a download each time.

**Termark + WebSocket tunnel** (recommended for hardened networks): Termark syncs authorized RDP assets, mints tickets automatically, and can tunnel the proxy over WebSocket through the existing Next Terminal Web address — no extra public RDP port.

> Docs: [RDP Proxy Server](/usage/rdp-server) · [Termark](/usage/termark) · [Agent Gateway](/usage/agent-gateway)

## When to Use It

Long Windows sessions, hotkey-heavy work, clipboard workflows, credential hygiene (no password distribution), audit/compliance retention, or deployments where you prefer not to expose an additional RDP port.

## Requirements

- Next Terminal ≥ v3.3.6, RDP assets added and authorized, RDP proxy enabled
- For direct mode: RDP proxy port mapped in `docker-compose.yaml`
- For WebSocket mode: Termark can reach the Next Terminal Web address
