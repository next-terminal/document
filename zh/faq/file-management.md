# 文件管理问题

先确认协议差异：SSH 文件系统直接操作目标主机，RDP 文件系统操作 Next Terminal 存储并通过网络驱动器与 Windows 中转。完整流程参阅[文件管理](/zh/usage/file-management)。

## SSH 文件系统内容为空或打不开

SSH 终端可用不代表 SFTP 一定可用。请检查目标服务器的 SFTP 子系统：

```shell
grep -E '^\s*Subsystem\s+sftp' /etc/ssh/sshd_config
```

常见配置包括：

```text
Subsystem sftp /usr/lib/openssh/sftp-server
```

或：

```text
Subsystem sftp internal-sftp
```

还要检查：

- 目标账号是否有权访问当前目录。
- `ChrootDirectory`、强制命令或 SFTP-only 策略是否改变了根目录。
- 网关路径是否允许同一 SSH 连接建立 SFTP 子系统。
- 当前资源授权和访问策略是否允许文件操作。

修改 `sshd_config` 前先验证配置，并按目标系统方式平滑重载 SSH 服务，避免锁死远程入口。

## 文件系统中没有上传、下载或删除按钮

按钮由当前资产授权关联的访问策略决定。管理员应在「资源授权 > 访问策略」检查上传、下载、新建、编辑、重命名、删除、复制和粘贴权限。

目录上传、批量下载和在线编辑还可能需要高级版本许可。修改策略后重新建立会话。

## 上传进度停在 99%

99% 通常表示文件已经从浏览器上传到服务端，但仍在向目标文件系统或存储传输。打开“文件进度”查看状态：

- `上传中`：浏览器仍在发送数据。
- `传输中`：服务端仍在写入最终目标。
- `失败`：查看错误详情并重试。

长时间不结束时，检查目标磁盘或存储配额、网络、文件权限和服务端日志。

## Windows 文件上传完成后找不到

浏览器上传的是 Next Terminal 存储，不会直接写入 Windows 的 `C:` 或 `D:`。

在 Windows 文件资源管理器中打开映射网络驱动器，找到文件后再复制到目标磁盘。找不到映射盘时参阅 [RDP 与 VNC：Windows 看不到网络驱动器](./rdp-vnc#windows-中看不到网络驱动器)。

## Windows 文件复制到映射盘后，浏览器看不到

- 确认 Windows 使用的是该资产绑定的同一个存储。
- 等待复制完成后点击浏览器文件系统的刷新按钮。
- 检查存储大小限制和文件名兼容性。
- 确认当前用户的下载策略允许查看和下载。

## 为什么文件日志中没有 Windows 内部复制记录？

浏览器对 Next Terminal 存储执行的上传、下载等动作会进入文件日志。Windows 内部从映射盘复制到系统盘，或从系统盘复制回映射盘，是 RDP 会话内部动作，应结合会话录像调查，不能只依赖文件日志。

## 删除的文件能恢复吗？

文件系统删除是永久操作，Next Terminal 不提供通用回收站。是否能够恢复取决于目标主机或存储本身的快照和备份。删除前应确认路径，并通过访问策略限制不需要删除权限的用户。
